#3 RSA Exposed: A Statistical Look at Public-Key Encryption

In our last assignment, we explored symmetric cryptography with the Caesar cipher, where a single secret key (the "shift") is used to both encrypt and decrypt. We saw how frequency analysis can break this cipher. Now, we enter the world of asymmetric cryptography with RSA, the algorithm that underpins much of modern internet security. But what happens if we apply RSA incorrectly, "letter by letter"?

What is Asymmetric (Public-Key) Cryptography?

Unlike the Caesar cipher, asymmetric cryptography uses a pair of keys:

  • Public Key: Can be shared with anyone. It is used to encrypt messages.
  • Private Key: Must be kept secret. It is the only key that can decrypt messages encrypted with its corresponding public key.

This solves a huge problem: how to securely exchange a secret key? With RSA, you don't have to. You can publish your public key, and anyone can send you a secure message.

The RSA Algorithm: An Overview

RSA (named after its inventors, Rivest, Shamir, and Adleman) bases its security on the difficulty of factoring very large numbers. The key steps are:

  1. Key Generation:
    • Choose two very large prime numbers, p and q (secret).
    • Calculate the modulus n = p * q (public).
    • Calculate Euler's totient phi(n) = (p-1) * (q-1) (secret).
    • Choose a public exponent e (often 65537 or 3), which must be coprime with phi(n).
    • Calculate the private exponent d such that (d * e) % phi(n) = 1.
  2. Encryption: To encrypt a message M (treated as a number), calculate: C = (M^e) % n.
  3. Decryption: To decrypt C, calculate: M = (C^d) % n.

The Homework's Premise: RSA "Letter by Letter"

Normally, RSA encrypts large blocks of data. For this assignment, we apply the RSA formula to every single letter (or, more precisely, its ASCII value). For example, we encrypt 'a' (ASCII 97), then 'b' (ASCII 98), and so on.

This creates a homophonic substitution cipher. Every 'a' in the original text will always be encrypted into the same number (97^e % n), and every 'b' will be encrypted into another fixed number (98^e % n). What does this mean from a statistical standpoint?

It means the frequency distribution is preserved! Just like in the Caesar cipher, the most frequent letter in the plaintext (like 'e' or 'a') will correspond to the most frequent *number* in the ciphertext. This is a fatal vulnerability that allows us to use the same frequency analysis from the previous assignment to break this flawed implementation of RSA.

From Statistics to Cryptanalysis: Breaking "Letter by Letter" RSA

Since the frequency is preserved, we can launch an attack. If we have a ciphertext (a long list of numbers), we can:

  1. Count the frequency of each number in the ciphertext.
  2. Count the frequency of each letter in a reference text (e.g., a long text in English or Italian).
  3. Create a decryption map: The most frequent number in the ciphertext *probably* corresponds to the most frequent letter in the reference text. The second most frequent corresponds to the second, and so on.

Correct RSA Implementation in C

The simulation above shows the required "letter by letter" approach and its attack. However, it's important to see how RSA is *correctly* implemented. The following C program implements the RSA algorithm to encrypt and decrypt a *single number* (which in practice would represent an entire block of text), not individual letters. This approach is secure against frequency analysis.

// Include standard I/O and math for the pow function
#include <stdio.h>
#include <math.h>

// Data type for large numbers (long long)
typedef long long ll;

// Function to efficiently calculate (base^exp) % mod
ll pow_mod(ll base, ll exp, ll mod) {
    ll res = 1;
    base %= mod;
    while (exp > 0) {
        if (exp % 2 == 1) res = (res * base) % mod;
        base = (base * base) % mod;
        exp /= 2;
    }
    return res;
}

// Function to find the modular inverse of 'a' modulo 'm'
// Finds 'x' such that (a*x) % m = 1
ll mod_inverse(ll a, ll m) {
    a = a % m;
    for (ll x = 1; x < m; x++) {
        if ((a * x) % m == 1) {
            return x;
        }
    }
    return 1; // Not found (should not happen if a and m are coprime)
}

int main(void) {
    // 1. Key Generation (using small primes for example)
    ll p = 53;
    ll q = 59;
    ll e = 3; // A common public exponent

    ll n = p * q;
    ll phi_n = (p - 1) * (q - 1);
    
    // Calculate the private key 'd'
    ll d = mod_inverse(e, phi_n);

    printf("--- RSA Parameters ---\n");
    printf("p = %lld, q = %lld, e = %lld\n", p, q, e);
    printf("Public Key (n, e): (%lld, %lld)\n", n, e);
    printf("Phi(n) = %lld\n", phi_n);
    printf("Private Key (d): %lld\n", d);
    
    // Message to encrypt (as a number)
    // Must be less than 'n'
    ll messaggio = 888;

    printf("\n--- Process ---\n");
    printf("Original Message (M): %lld\n", messaggio);

    // 2. Encryption: C = (M^e) % n
    ll crittografato = pow_mod(messaggio, e, n);
    printf("Encrypted (C): %lld\n", crittografato);

    // 3. Decryption: M = (C^d) % n
    ll decrittografato = pow_mod(crittografato, d, n);
    printf("Decrypted (M'): %lld\n", decrittografato);

    // Verification
    if (messaggio == decrittografato) {
        printf("\nSuccess: The message was recovered!\n");
    } else {
        printf("\nError: Decryption failed.\n");
    }
    
    return 0;
}

As you can see, the correct implementation of RSA is mathematically intensive and operates on numbers, not letters. Its security comes from the difficulty of finding d given only n and e, which would require factoring n into its prime components p and q, an extremely difficult operation for very large numbers.

The vulnerability we exploited in the simulation is not a weakness of RSA itself, but a weakness of the implementation. Applying any deterministic cipher (where 'a' *always* becomes 'x') "letter by letter" will always create a substitution cipher, which is immediately vulnerable to frequency analysis, as we have demonstrated.
